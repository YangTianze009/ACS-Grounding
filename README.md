# LVLM Object Detection — Self-Improving Small Object Localization

Codebase for the paper *Self-Improving Small Object Localization via Attention-based Candidate Selection in LVLMs*.

Reproduces all numbers in the main results table for **Qwen2.5-VL-7B** and **InternVL-3.5-8B** on small-object detection (MS COCO + Objects365, 2,225 instances each).

The codebase implements the two variants of the **Attention-based Candidate Selection (ACS)** framework:

- **ACS-Learned** — regressor-based selector. A lightweight CNN (the *Attention-IoU Regressor*) predicts the IoU of each candidate bbox from its attention maps; the candidate with the highest predicted IoU is selected.
- **ACS-Free** — training-free selector. Ranks candidates by attention entropy on a small set of discriminative (layer, head) pairs identified through gradient attribution of the trained regressor.

Plus 6 baselines for comparison: Greedy · Pass@1 · FirstValid · TokEntropy · MajVote · MeanBBox · Smallest.

> **Internal code naming.** In the source the two variants are still referred to as **`regression`** (= ACS-Learned) and **`entropy`** (= ACS-Free). The mapping is documented in the *Methods* table below.

All 96 (model × dataset × τ × method) cells in [`SUMMARY.tsv`](SUMMARY.tsv) reproduce the paper table within ±0.001 rounding tolerance. See [`FINAL_TABLE.md`](FINAL_TABLE.md) for the rendered master table.

## Where the data lives

The raw sampled responses (10 LVLM responses per image with attention maps) and the regressor's processed input tensors are **outside** this repo. On the authors' setup they live under `/scratch/ty45972/MLLM_object_detection/` with the following layout:

```
<DATA_ROOT>/
├── object_detection_Qwen/
│   ├── model_response/                                # raw LVLM outputs (one .pkl per image)
│   │   └── {COCO,Objects365}/testing/single_object/
│   │       └── bbox_attention_temp_<τ>_top_p_0.9_response_10/
│   └── regression_training/
│       └── processed_data/                             # tensors fed to ACS-Learned
│           └── {COCO,Objects365}/single_object/
│               └── temp_<τ>_top_p_0.9_response_10/
│
└── object_detection_InternVL/
    ├── model_response/
    │   └── {COCO,Objects365}/testing/
    │       └── bbox_attention_temp_<τ>_top_p_0.9_response_10/
    └── regression_training/
        └── processed_data/
            └── {COCO,Objects365}/
                └── temp_<τ>_top_p_0.9_response_10/
```

`<τ> ∈ {0.5, 0.7, 1.0}` is the temperature used at sampling time.

**To run on your own machine**, place the data anywhere and update `DATA_ROOT` (or the equivalent variable) at the top of:

- `qwen2.5_small/baselines/run_baseline.sh`
- `qwen2.5_small/entropy/run_select.sh`, `run_eval.sh`
- `qwen2.5_small/regression/run_test.sh`, `config.yaml`
- the matching `internvl_3.5_small/*` scripts

Each `pkl` in `model_response/` contains, per image: the predicted bbox candidates, their attention maps from every layer and head, the ground-truth bbox, and image metadata. `processed_data/` is the pre-extracted attention tensors that the regressor consumes (produced once by `regression/data_processing.py`).

The COCO / Objects365 source images themselves are the standard public versions and are not redistributed here; download them from the official sources.

## Stage 0 — Data generation (optional)

The selection / regression / evaluation pipelines below consume the pre-computed `model_response/*.pkl.gz` files. These are produced by the extraction code in `<model>/extraction/`:

- [`<model>/extraction/bbox_attention_extractor.py`](qwen2.5_small/extraction/bbox_attention_extractor.py) — low-level extractor (runs the LVLM once per image and saves the per-coordinate attention maps).
- [`<model>/extraction/batch_bbox_attention_processor.py`](qwen2.5_small/extraction/batch_bbox_attention_processor.py) — driver. Iterates over the dataset (COCO / Objects365 single- or multi-object split) and writes one pkl per image into `<DATA_ROOT>/.../model_response/`.

```bash
# Qwen2.5-VL (single A6000, ~6-8 h for 2,225 images × 10 responses at τ=1.0)
cd qwen2.5_small/extraction
python batch_bbox_attention_processor.py \
    --dataset COCO --data_type testing --object_num single \
    --temperature 1.0 --top_p 0.9 --top_k 100 --num_responses 10

# InternVL-3.5 (similar, slightly slower; uses --device "0, 1" by default)
cd internvl_3.5_small/extraction
python batch_bbox_attention_processor.py \
    --dataset COCO --data_type testing --object_num single \
    --temperature 1.0 --top_p 0.9 --top_k 100 --num_responses 10
```

**Requirements** (beyond the selection-side deps):

- The LVLM weights — `Qwen2.5-VL-7B-Instruct` and `InternVL3_5-8B-HF`. The driver scripts have hard-coded paths near the top (`/data2/Tianze/weights/...`); edit to your local path.
- The dataset's image files and a CSV listing target instances (the driver expects a specific dataset layout — see `setup_config()` inside each driver).
- A CUDA-capable GPU (~20-30 GB VRAM).

**Skip Stage 0 if** you already have the pkl files at `<DATA_ROOT>/.../model_response/` (e.g., from the authors). The Stage 1+ pipelines below read those pkls directly.

## Quick start

```bash
# 1. Run all 6 baselines × 12 configs (2 models × 2 datasets × 3 temperatures)
bash run_all_baselines.sh

# 2. ACS-Learned (regressor-based selector) on all 12 configs
for model in qwen2.5_small internvl_3.5_small; do
  for ds in COCO Objects365; do
    for t in 0.5 0.7 1.0; do
      bash $model/regression/run_test.sh $t $ds
    done
  done
done

# 3. ACS-Free (training-free entropy selector) on all 12 configs
for model in qwen2.5_small internvl_3.5_small; do
  for ds in COCO Objects365; do
    for t in 0.5 0.7 1.0; do
      cd $model/entropy && bash run_select.sh $t $ds && bash run_eval.sh $t $ds && cd ../..
    done
  done
done

# 4. Inspect results
column -t -s$'\t' SUMMARY.tsv | less
```

Total wall time on a single A6000: **~3 hours** (baselines are the bottleneck; ACS-Learned needs GPU, ~30 min total).

## Prerequisites

### Python environments

Two conda envs (Qwen2.5-VL and InternVL-3.5 mostly share deps but differ in `transformers` / vision-tower versions):

```bash
conda create -n Qwen      python=3.10
conda create -n internvl  python=3.10

# in each env install: torch, transformers, accelerate, pandas, numpy,
# pyyaml, tqdm, pillow, scipy, seaborn
```

The shell scripts default to:

- `/home/$USER/.conda/envs/Qwen/bin/python3` — Qwen2.5-VL
- `/home/$USER/.conda/envs/internvl/bin/python3` — InternVL-3.5

Edit `PYTHON=...` near the top of each `<model>/{baselines,entropy,regression}/run_*.sh` if your paths differ.

### ACS-Learned checkpoints

Trained CNN checkpoints are **not committed**. Either re-train (see below) or place a `.pth` file at:

- Qwen2.5-VL: `qwen2.5_small/regression/runs/single_object/temp_1.0_top_p_0.9_response_10/enhanced_bbox_regressor_20250920_181221/best_model.pth`
- InternVL-3.5: `internvl_3.5_small/regression/runs/temp_1.0_top_p_0.9_response_10/bbox_regressor_20251014_210145/best_model.pth`

The `MODEL_CKPT=...` line in each `<model>/regression/run_test.sh` points at this path; edit if you save the checkpoint elsewhere.

The CNN is trained once on temp=1.0 data and used at inference for all τ ∈ {0.5, 0.7, 1.0}.

## Methods

| Paper name | CLI invocation | Algorithm |
|---|---|---|
| **Greedy** | (separate setup, deterministic decoding) | response_1, no sampling, temperature = 0 |
| **Pass@1** | `run_baseline.sh <DS> <τ> pass@1` | always `response_1, bbox_1`, no validity check |
| **FirstValid** | `run_baseline.sh <DS> <τ> first_valid` | first response with a parseable, coord-order-valid bbox |
| **TokEntropy** | `run_baseline.sh <DS> <τ> vocab_entropy` | candidate with lowest summed vocab entropy over 4 coord tokens |
| **MajVote** | `run_baseline.sh <DS> <τ> basic_mode` | per-coord majority vote across 10 candidates → synthetic bbox |
| **MeanBBox** | `run_baseline.sh <DS> <τ> mean_bbox` | per-coord arithmetic mean → synthetic bbox |
| **Smallest** | `run_baseline.sh <DS> <τ> smallest` | candidate with min area |
| **ACS-Free** *(paper: training-free variant)* | `bash entropy/run_select.sh <τ> <DS> && bash entropy/run_eval.sh <τ> <DS>` | rank-sum of attention entropy across 3 discriminative heads per coordinate (12 heads total) |
| **ACS-Learned** *(paper: regressor-based variant)* | `bash regression/run_test.sh <τ> <DS>` | trained Attention-IoU Regressor; argmax over predicted IoU per image |

### `run_baseline.sh` cheat sheet

```bash
cd <model>/baselines

# Single method, single config
bash run_baseline.sh COCO 0.5 pass@1
bash run_baseline.sh Objects365 1.0 first_valid

# All 6 baselines for one config (pkl-load batching → ~5× faster than per-method)
bash run_baseline.sh COCO 0.5 all

# Methods: pass@1 | first_valid | vocab_entropy | mean_bbox | basic_mode | smallest | all   (default: all)
# DS:      COCO | Objects365
# τ:       0.5 | 0.7 | 1.0
```

### Top-level driver

```bash
# Cover all 12 configs × all baselines
bash run_all_baselines.sh

# Subset: one method across all configs
bash run_all_baselines.sh pass@1

# One specific config (any one method)
bash run_all_baselines.sh qwen2.5_small COCO 0.5 first_valid
```

## ACS-Free — discriminative heads

Both ACS-Free wrappers (`<model>/entropy/run_select.sh` / `run_eval.sh`) ship the discriminative (layer, head) pairs (n = 3 per coordinate) identified by gradient attribution of the trained Attention-IoU Regressor:

- **Qwen2.5-VL**: x1 = (20,15)(21,22)(19,23) · y1 = (20,14)(20,19)(18,15) · x2 = (19,27)(19,23)(18,15) · y2 = (20,26)(14,16)(20,16)
- **InternVL-3.5**: x1 = (21,19)(23,30)(18,5) · y1 = (24,31)(21,28)(24,21) · x2 = (21,19)(21,23)(22,0) · y2 = (21,23)(24,11)(21,29)

Selection is the rank-sum of per-coordinate attention-entropy ranks across the 3 heads.

## Reproducibility notes

- 96 of 96 (method × model × dataset × τ) cells in `SUMMARY.tsv` reproduce the paper within ±0.001 rounding tolerance.
- All baseline / ACS-Free scripts are deterministic given the same input pkl files. The only GPU step is `regression/test.py` (ACS-Learned); we save its bbox_id output to CSV, so the downstream pipeline is deterministic too.
- The Attention-IoU Regressor is trained once on temp=1.0 data and used unchanged across τ ∈ {0.5, 0.7, 1.0}. No per-temperature retraining.

### Re-training ACS-Learned (optional)

```bash
cd <model>/regression

# 1. One-time data prep: raw model_response → processed_data tensors
python data_processing.py --config config.yaml

# 2. Train
python train.py --config config.yaml

# 3. Test (update MODEL_CKPT in run_test.sh to point at the new weights)
bash run_test.sh 1.0 COCO
```

Expected training time: ~2 h on a single A100/H100 per (model, dataset). The released weights were trained on temp = 1.0 only.
